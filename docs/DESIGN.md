# 梦幻西游工具箱 设计文档

> 版本：v1.1 · 更新日期：2026-08-02
> 适用范围：桌面端 Windows（开发环境）/ 打包 EXE（运行环境）

## 一、项目概述

**梦幻西游工具箱**（menghuan_tools）是基于 Python + Flet 框架开发的桌面辅助应用，定位为「**只读识别 + 信息辅助**」工具集，不涉及自动操作游戏、不读取游戏内存、不修改封包，所有数据通过屏幕 OCR 与公开资源获取。

### 核心价值
- 整合账号管理、记账、养成规划、抓鬼辅助等日常需求到统一界面
- 复用同一套 OCR 引擎与窗口锁定能力，避免重复加载模型
- 离线运行（地图资源、OCR 模型均打包到本地）

## 二、当前架构

### 目录结构
```
menghuan_tools/
├── main.py                  # 应用入口，页面切换与生命周期管理
├── core/                    # 业务逻辑层（数据持久化）
│   ├── data_manager.py      # 账号数据管理（加密存储）
│   ├── accounting_db.py     # 记账本 SQLite
│   └── growth_db.py         # 养成规划 SQLite
├── pages/                   # UI 页面层（Flet 控件）
│   ├── account_page.py      # 账号管理
│   ├── accounting_page.py   # 记账本
│   ├── growth_page.py       # 养成规划
│   └── ghost_hunter_page.py # 抓鬼辅助（含 OCR/窗口锁定/地图预测）
├── utils/                   # 工具层
│   ├── platform_utils.py    # 应用数据目录适配
│   └── logger_setup.py      # 日志配置
├── assets/maps/             # 离线地图资源（22 张）
├── models/easyocr/          # OCR 模型（备用回退）
├── main.spec                # PyInstaller 打包配置
└── requirements.txt
```

### 分层职责
| 层 | 职责 | 依赖方向 |
|---|---|---|
| `pages/` | UI 渲染、用户交互、页面生命周期 | → `core/` → `utils/` |
| `core/` | 数据持久化、业务规则 | → `utils/`（仅日志/路径） |
| `utils/` | 跨层基础设施 | 无内部依赖 |

### 关键技术决策
| 决策 | 选择 | 原因 |
|---|---|---|
| UI 框架 | Flet 0.86+ | 跨平台、Python 原生、组件丰富 |
| OCR 引擎 | RapidOCR (onnxruntime) | 纯 CPU、模型小、中文识别准确 |
| 截图 | mss | 高性能、支持多显示器 |
| 窗口操作 | ctypes + win32 API | 无需 pywin32 依赖 |
| 数据存储 | JSON（账号）+ SQLite（记账/养成） | 轻量、无服务端 |
| 打包 | PyInstaller | 单 EXE 分发 |

### 跨页面共享能力
- **OCR 引擎单例**：`CoordinateOCR._ocr_engine` 类变量 + 双重检查锁，所有页面复用
- **窗口锁定**：`find_window_by_title` 自动识别梦幻西游主窗口（排除聊天窗口）
- **区域框选**：Tkinter 透明覆盖层 + `grab_set()` 强制焦点
- **相对坐标持久化**：保存相对窗口偏移量，窗口移动后自动重算
- **生命周期管理**：`main.py` 切换页面前调用 `cleanup()` 释放资源

## 三、已实现模块清单

### 1. 账号管理（AccountPage）
- 增删改查、搜索、复制账号密码
- AES 加密存储（基于密码派生密钥）
- 导入/导出（带密码保护的 base64 文件）

### 2. 记账本（AccountingPage）
- 收支记录、分类统计
- SQLite 持久化
- matplotlib 图表展示

### 3. 养成规划（GrowthPage）
- 角色属性记录
- 目标管理
- SQLite 持久化

### 4. 抓鬼辅助（GhostHunterPage）
- **OCR 坐标识别**：地图面板/抓鬼任务双区域识别
- **窗口锁定**：自动识别梦幻西游主窗口（排除聊天窗口），支持窗口拖动后重新锁定
- **区域框选**：可视化框选地图面板和抓鬼任务区域，相对坐标持久化
- **图像预处理**：放大 3 倍 + CLAHE 增强 + 多颜色通道提取（红/黄/绿/橙/蓝）+ 自适应阈值 + 形态学滤波
- **地图自动渲染**：OCR 识别 `[地图名(x,y)]` 自动加载对应地图
- **鬼位置预测**：基于学习数据（`ghost_hunter_learning.json`）预测鬼在地图上的实际位置
- **悬浮窗叠加**：Tkinter 透明窗口叠加在游戏上方显示预测范围
- **反馈学习**：用户标注真实坐标后更新学习数据

### 4.2 关键启示
1. **OCR + 题库** 是答题器标配，本项目已有 RapidOCR，复用成本极低
2. **摆摊物价识别** 是商业价值最高的方向（参考 175xyq.com）
3. **场景识别**（战斗/城镇/对话）是高级辅助的基础，可作为基础设施层
4. **远程控制/多开** 适合五开玩家，但开发复杂度高
5. **合规边界**：参考 [mhxy-pk-vision-assistant](https://github.com/JKevinXu/mhxy-pk-vision-assistant) 的「只读视觉识别」原则，本项目应坚持不自动操作游戏

## 五、新模块建议

按「**复用度高 / 开发成本低 / 用户价值大**」三维评分排序：

### 优先级 P0（强烈推荐）

#### 5.1 答题器模块（QuizAssistantPage）⭐⭐⭐⭐⭐
**复用度**：⭐⭐⭐⭐⭐（OCR 引擎、窗口锁定、区域框选全部复用）
**开发成本**：低（核心是题库 + 模糊匹配）
**用户价值**：⭐⭐⭐⭐⭐（科举、三界情缘、师徒、房都尉等高频场景）

**功能设计**：
- 题库管理：CSV/JSON 格式导入，支持模糊搜索（编辑距离匹配）
- 一键识别：快捷键触发 OCR 截取答题区域，自动匹配答案
- 答案展示：悬浮窗显示 Top3 答案 + 置信度
- 题库补全：未匹配题目支持手动录入答案，持续积累
- 多场景模板：不同答题活动（科举/三界/师徒）的识别区域预设

**技术要点**：
- 题库存储：SQLite（`quiz_bank.db`），字段 `id, question, answer, category, hit_count`
- 匹配算法：TF-IDF + 编辑距离，或直接使用 `rapidfuzz` 库
- 快捷键：`pynput` 全局热键（Ctrl+Shift+A）

**预估工作量**：题库 200 条 + UI + 匹配逻辑

#### 5.2 数据统计中心（StatsDashboardPage）⭐⭐⭐⭐⭐
**复用度**：⭐⭐⭐⭐（整合现有各模块数据）
**开发成本**：低（主要是图表 + 聚合查询）
**用户价值**：⭐⭐⭐⭐⭐（量化游戏投入产出）

**功能设计**：
- 抓鬼统计：本日/本周/本月抓鬼次数、地图分布、预测准确率
- 记账汇总：游戏收支趋势、分类占比
- 养成进度：属性提升曲线、目标达成率
- 时间投入：各模块使用时长统计
- 可视化：折线图、饼图、热力图（地图分布）

**技术要点**：
- 复用 `matplotlib`（记账本已用）
- 数据来源：`ghost_hunter_learning.json` + `accounting.db` + `growth.db`
- 新增 `core/stats_aggregator.py` 做跨模块聚合查询

### 优先级 P1（推荐）

#### 5.3 宝图任务模块（BaoTuPage）⭐⭐⭐⭐
**复用度**：⭐⭐⭐⭐⭐（地图资源、OCR、窗口锁定全部复用）
**开发成本**：中（需挖掘宝图坐标体系）
**用户价值**：⭐⭐⭐⭐（宝图任务是日常收益大头）

**功能设计**：
- 宝图坐标 OCR 解析（背包宝图截图）
- 地图定位渲染（复用 `assets/maps/`）
- 宝图记录与统计（已挖/未挖、总收益）
- 挖宝路线规划（按地图聚合，减少跑图）

**技术要点**：
- 复用 `GhostCoordinatePredictor` 的地图坐标映射逻辑
- 新增 `core/baotu_db.py` 存储宝图记录

#### 5.4 活动日程模块（ActivityCalendarPage）⭐⭐⭐⭐
**复用度**：⭐⭐（独立模块，仅复用 UI 框架）
**开发成本**：低（不依赖 OCR）
**用户价值**：⭐⭐⭐⭐（避免错过限时活动）

**功能设计**：
- 周常/日常活动时间表（科举、帮战、迷宫、押镖等）
- 系统通知提醒（`plyer` 跨平台通知）
- 活动奖励记录
- 自定义提醒规则

**技术要点**：
- 数据存储：JSON 配置文件
- 通知：`plyer` 库（Windows toast 通知）
- 后台定时：`threading.Timer` 或 `APScheduler`

#### 5.5 摆摊物价监控（MarketMonitorPage）⭐⭐⭐⭐
**复用度**：⭐⭐⭐（OCR 复用，但需新开发摆摊识别）
**开发成本**：高（摆摊界面识别复杂、需建物品库）
**用户价值**：⭐⭐⭐⭐⭐（商业价值最高）

**功能设计**：
- 摆摊界面 OCR 识别（物品名 + 价格）
- 历史价格记录与趋势图
- 捡漏提醒（低于历史均价 X% 的物品）
- 藏宝阁数据爬取（参考 cbg.163.com）
- 物品价格排行榜

**技术要点**：
- 数据存储：SQLite（`market_prices.db`）
- 爬虫：`requests` + 解析（注意反爬，建议仅做公开数据查询）
- 图表：复用 matplotlib

## 六、技术选型补充

### 新增依赖建议
| 库 | 用途 | 模块 | 大小 |
|---|---|---|---|
| `rapidfuzz` | 字符串模糊匹配 | 答题器 | ~500KB |
| `plyer` | 跨平台通知 | 活动日程 | ~200KB |
| `apscheduler` | 定时任务调度 | 活动日程 | ~1MB |
| `plotly` （可选） | 交互式图表 | 统计中心 | ~20MB |

> 注意：新增依赖需同步更新 `requirements.txt` 和 `main.spec` 的 `hiddenimports`

### 数据存储规范
- 业务数据：`<app_data_dir>/<module>.db`（SQLite）
- 配置数据：`<app_data_dir>/<module>_config.json`
- 学习数据：`<app_data_dir>/<module>_learning.json`
- 日志：打包模式下 `<exe_dir>/log/app.log`

### 打包注意事项
- 所有 `core.*` 和 `utils.*` 模块需加入 `main.spec` 的 `hiddenimports`
- 资源文件（地图、模型）通过 `datas` 配置打包
- RapidOCR 模型随包发布，避免运行时下载

## 八、合规与安全声明

### 合规边界
本项目坚持「**只读识别 + 信息辅助**」原则：
- ✅ 屏幕截图 + OCR 识别公开可见信息
- ✅ 数据本地存储，不上传服务器
- ✅ 用户手动操作游戏，工具仅提供信息
- ❌ 不读取/修改游戏内存
- ❌ 不解析/伪造网络封包
- ❌ 不自动操作游戏（点击/按键）
- ❌ 不绕过反外挂机制

### 数据安全
- 账号密码加密存储（PBKDF2 + Fernet）
- 导出文件支持密码保护
- 不收集任何用户数据
- 日志仅记录运行状态，不含敏感信息

### 免责声明
- 本工具仅供学习研究，使用者需自行承担风险
- 不保证功能持续可用（游戏更新可能导致 OCR 失效）
- 严禁用于商业用途
